# Application audit and AD lab validation — 2026-10-12

## Outcome and scope

The application was reviewed and changed, including its LDAP collection, evidence classification, scoring/publication boundaries, assessment identity, history, takeover graph, HTML reporting and export workflows. Existing working-tree changes were retained; this is not a claim that every changed file in `git diff` was authored during this audit.

AtilKurt is a read-only Active Directory assessment CLI. Its critical workflow is connection → directory collection → registered analyzers → evidence/review/scoring → HTML and integration/client exports. Optional workflows include checkpoints, offline reprocessing, history, scope enforcement and focused verification. A finding, a directory permission, an exploitable prerequisite and a completed Domain Admin takeover are different claims. This distinction governs the changes below.

Baseline: 789 tests passed and Ruff passed before the audit changes. The final test results and live artifacts are recorded in `output/audit-20261012/`. This directory is ignored by Git and its assessment artifacts are private. No dependency was added, no deployment was performed, and the directory was not modified.

**Live LDAP passed. Live TLS did not pass.** The DC closes LDAPS before completing TLS and rejects StartTLS as unavailable. This is an unresolved endpoint/environment limitation, not a test counted as successful.

## Confirmed defects and changes

Each entry describes a reproducible condition, cause, effect and verification. Severity describes the application defect, not the severity of a directory finding.

### 1. High — quoted credentials leaked through redaction/publication

Files: `core/directory_redaction.py`, `reporting/client_report.py`, `AtilKurt.py`.

A description such as `password="first second third"` previously left the second and third words visible because the expression consumed only non-whitespace characters. Legacy offline inventories could also bypass the live redaction boundary and republish the original values into JSON/checkpoints. Users sharing a report could disclose secrets.

The shared credential matcher now handles quoted, escaped and unterminated values; publication and checkpoint boundaries redact copies of the inventory. Noncredential words such as `bypass=true` are preserved. Regression tests cover secret tails, offline HTML/JSON publication and checkpoint serialization. The supplied bind password was also checked for absence from the final live output artifacts without storing it in the test script.

### 2. High — output paths could overwrite a trusted CA input

File: `AtilKurt.py:validate_output_paths`.

Using the CA bundle as an output destination, including through a hardlink or symlink, could overwrite a TLS trust input. CA files now participate in input/output alias validation. Regression tests reproduce all three alias forms and assert rejection before writing.

### 3. High — incomplete offline assessments could report success

Files: `AtilKurt.py`, `reporting/html_report.py`.

Reprocessing a snapshot whose collection/analysis was partial could lose the nonzero completion status. An explicit `unknown` collection status could also look complete, especially with an empty result set. The CLI now preserves the incomplete exit code, publication displays the uncertainty, and an empty incomplete inventory does not earn a clean score. Tests cover partial, failed and unknown states and partial analysis execution.

### 4. High — identity matching could associate the wrong principal

Files: `core/assessment_identity.py`, `analysis/assessment_da_paths.py`, `AtilKurt.py`.

A same-name candidate could win over an authoritative DN/SID, and an exported snapshot did not preserve the bind identity. That could attribute another account's rights to the session or lose reachability context on offline reprocessing.

DN and present SID/token evidence now take precedence; ambiguous matches stay unresolved. JSON exports retain `assessment_identity`, and offline import validates and restores it. Regression tests include name/SID conflicts, duplicate labels and a real offline CLI round trip with LDAP explicitly prohibited.

### 5. Medium — history KPIs could be contaminated by offline reviews

File: `core/assessment_history.py:finding_kpi_snapshot`.

The selected previous live scan was combined with mutable finding state subsequently changed by an offline review. A trend could therefore compare values from different observations. KPIs now come from the selected fresh run's immutable summary, with deterministic ordering. Missing legacy counts are unknown rather than invented. Tests replay live → offline review → subsequent comparison.

### 6. Medium — FILETIME conversion depended on the workstation timezone

Files: `core/ad_security.py`, `core/collectors/user_collector.py`, `core/collectors/computer_collector.py`.

Local `fromtimestamp` conversion shifted directory timestamps; extreme values could overflow. Both collectors now use an explicit UTC epoch and integer arithmetic, including AD's never/zero sentinels and invalid ranges. Tests cover both collectors, UTC offsets and oversized values. This does not claim that every older analyzer's age calculation was rewritten.

### 7. Medium — historical lockout timestamps were treated as current lockouts

File: `core/collectors/user_collector.py`.

A nonzero `lockoutTime` can remain after a timed lockout ends. The previous inference therefore mislabelled accounts as currently locked. The collector now requests `msDS-User-Account-Control-Computed` and uses its LOCKOUT bit. If current flags are unavailable and only historical evidence exists, the state remains unknown. The old test that asserted nonzero always means locked was corrected, and current/expired/unknown cases were added.

### 8. High — absent optional AD deployments caused false partial scans

Files: `core/optional_directory.py`, `analysis/extended_ldap_analyzer.py`, `analysis/sccm_attack_surface_analyzer.py`, `analysis/adcs_control_plane_analyzer.py`, `analysis/hybrid_identity_v2_analyzer.py`.

The original live scan issued searches directly against absent Exchange, NTAuth, SCCM and AD FS containers. The legacy DNS probe also used `Microsoft DNS` instead of `MicrosoftDNS`; the SCCM probe requested a schema-dependent attribute that the analysis did not use. The result was five failed query records, four partial analysis steps and exit code 2 despite reachable LDAP.

Optional subtrees are now discovered by an exact escaped DN filter from an existing naming context before searching them. The unused SCCM schema attribute was removed, an empty SCCM result no longer creates a deployment finding, and Exchange discovery counts server objects. No global error suppression was added: transport/permission/schema failures remain query failures. Empty discovery means **not observed with this token**, not proof that a service cannot exist.

Offline tests assert the absent-base behavior and exception propagation. Live retests complete 100 audited queries with zero failed queries and exit code 0.

### 9. High — AD CS descendants were labelled as PKI root control

File: `analysis/adcs_control_plane_analyzer.py`.

A subtree search on Public Key Services treated every descendant as `pki_root`. In the lab, a Cert Publishers grant on AIA became a critical PKI-root takeover finding. The root query and local DN check now require the exact root object; separately scoped CA/template/NTAuth/OID checks remain.

Observed dangerous PKI ACLs remain security findings. A separate `takeover_requires_validation` boundary requires effective control, active publication/trust and a concrete privileged authentication chain before presenting them as an open takeover option. This preserves the risky ACL rather than hiding it to improve the score. Tests verify both descendant exclusion and preservation of an observed NTAuth ACL as a finding pending takeover validation.

### 10. High — current memberships and delegated administration overstated takeover

Files: `core/ad_identity.py`, `core/ad_security.py`, `analysis/privilege_escalation.py`, `analysis/attack_graph_v2_analyzer.py`, `analysis/assessment_da_paths.py`.

Pure membership chains were described as new privilege escalation. DNS/operator administration was also included in the broad privileged-group set and could be interpreted as Tier-0 itself. The independently read live chain `erin.kerrin → Senior management → DnsAdmins` proves sensitive existing delegation; it does not establish Domain Admin membership.

The graph now propagates **existing membership**, separates `sensitive_access` from Tier-0 targets, and reports current access separately. Domain Admins, Enterprise Admins, Schema Admins, writable Domain Controllers and BUILTIN Administrators are recognized by authoritative role identity. Distribution groups cannot provide security-token rights. Renamed privileged groups, primary groups and member backlinks are handled; an unrelated same-CN group in another OU cannot supply a membership edge.

Regression tests cover all these cases and prove that a real control edge still creates a path. The prior graph test that expected a membership-only chain to be an attack was corrected rather than deleted.

### 11. High — session options were reported as proven Tier-0 reachability

File: `analysis/assessment_da_paths.py:build_assessment_account_view`.

The boolean `reaches_tier0` included generic authenticated-session techniques such as Kerberoasting or machine quota. In the lab it was `true` for `cuma` despite zero graph routes. It now depends on evidenced graph reachability; `has_assessment_options` separately records available investigation options. `takeover_tested` is explicitly false. A regression verifies a Kerberoasting option without a Tier-0 route.

### 12. Medium — evidence could disappear or graph components could disconnect

Files: `analysis/domain_admin_takeover_analyzer.py`, `analysis/attack_graph_v2_analyzer.py`.

If a technique had one supported object and another pending object, the pending object was omitted from the map. Both buckets now retain their objects independently; one technique may legitimately appear in both sections.

Component graphs also used different node IDs for the same SID. Components now join inventory nodes by SID or DN, preserving known identity and privilege information. A regression proves that a SID alias creates the expected real control path and does not revoke the target's known membership.

### 13. Medium — route enumeration explored unreachable dense components

File: `analysis/assessment_da_paths.py:enumerate_tier0_routes`.

Depth-limited DFS still enumerated many simple paths in a dense component with no Tier-0 destination. A reverse BFS now prunes unreachable nodes and paths that cannot finish within the remaining depth. Regression tests preserve reachable simple routes.

A same-process synthetic comparison used 15 nodes, 182 edges, one source and depth six. Five runs gave a median **258.725 ms** for the reference with pruning removed and **0.062 ms** for the current function; both returned no routes. This is a deliberately adverse route-enumeration case, not a measured end-to-end scan speedup or a claim about production directory scale. See `route-benchmark.json`.

### 14. Medium — report command templates accepted executable metacharacters

Files: `analysis/domain_admin_takeover_playbooks.py`, `analysis/takeover_evidence.py`.

Directory object labels are untrusted input. Direct interpolation into mixed shell/PowerShell command templates could turn a copied example into additional commands. Legacy templates now replace unsafe substitutions with explicit `*_REQUIRES_MANUAL_REPLACEMENT` markers while keeping the original label in explanatory text. New per-finding LDAP examples escape filters and quote each shell argument. Tests cover command substitution, quotes, newlines, LDAP metacharacters and HTML injection.

Examples remain examples: no generated command is automatically executed. Operators must still fill placeholders and review tool-specific syntax, especially object names requiring context-specific quoting.

### 15. Low — search fields and tab state were inaccessible to assistive technology

Files: `reporting/report_sections/{acl_section,directory_section,risk_sections,dashboard_section}.py`, `reporting/saas_report_template.py`.

Several search inputs had only placeholders, and tab navigation changed visual classes without updating `aria-selected`. Search controls now have accessible names and navigation updates selection state. Chromium tests visit all 40 tabs in each language, inspect visible search controls, exercise filters/details and open the mobile menu. This is targeted accessibility validation, not a full WCAG certification.

## Reporting improvements

The takeover map retains its 34-technique catalog and detailed technique roadmaps. It now adds:

- A visible evidence boundary separating observed conditions, existing access, graph routes and executed takeover proof.
- Current Tier-0 membership and sensitive delegated membership in a separate expandable section.
- A dossier for every mapped supported or pending finding: stable finding ID, target DN, trustee, observed permissions, observation, prerequisites, expected evidence, falsifying conditions, read-only LDAP PoC and retest instructions.
- Separate supported/pending objects within the same technique, without dropping uncertain observations.
- An explicit distinction between bind-account reachability and domain-wide assessment options.
- Turkish presentation labels, accessible controls and retained machine-readable evidence in JSON.

The lab reports contain 53 finding dossiers: 40 in supported technique cards and 13 in pending cards. The PoCs ask for passwords interactively; none contain the supplied password. DCSync examples require both replication rights at the domain root and distinguish legitimate synchronization/DC principals from unauthorized delegation. They do not treat a single right or an OU-scoped grant as sufficient.

## TLS blocker and retest procedure

The application exits 1 with `Connection reset by peer` for verified LDAPS. A diagnostic run with certificate validation disabled fails the same way; it is not a workaround. Verified StartTLS also exits 1 with `unavailable`. OpenSSL independently reproduces LDAPS reset with TLS 1.2 and the DC's actual SNI name, and StartTLS returns LDAP result code 52. No server certificate is received, so certificate identity/trust cannot yet be validated.

The observations establish that a usable TLS endpoint is unavailable from this client. They do **not** alone distinguish missing DC certificates, Schannel configuration, an intervening device or another server-side cause. Inspect DC certificate/private-key availability and Schannel/Directory Service events. Microsoft documents the required Server Authentication certificate, DC DNS identity and private-key requirements in [Enable LDAP over SSL](https://learn.microsoft.com/en-us/troubleshoot/windows-server/identity/enable-ldap-over-ssl-3rd-certification-authority) and [Troubleshoot LDAP over SSL](https://learn.microsoft.com/en-us/troubleshoot/windows-server/active-directory/ldap-over-ssl-connection-issues).

After the endpoint is repaired, test with its certificate-matching FQDN, working DNS resolution and the issuing CA bundle:

```sh
.venv/bin/python AtilKurt.py -d lab.local -u cuma \
  --dc-ip WIN-2KHLLK2GC76.lab.local --ssl \
  --ca-certs-file /path/to/lab-ca.pem --no-progress \
  --output output/lab-ldaps.html --json-export output/lab-ldaps.json
```

The password is prompted. Do not treat `--no-validate-cert` as successful certificate verification. No DC configuration or certificate-store changes were made by this audit.

## Verification and remaining coverage limits

- Full pytest suite: **853 passed**, with two upstream ldap3/pyasn1 deprecation warnings. Ruff, package dependency consistency, JavaScript syntax, shell syntax, ShellCheck and `git diff --check` passed. The system setuptools installation successfully built the wheel without adding dependencies to the application.
- The built-in labelled quality dataset passes 49/49 cases across nine evaluated families. This measures those fixtures only. No labelled representative production dataset is available; no production false-positive/false-negative rate is asserted.
- Chromium tests cover desktop navigation, visible search names, all category filters, opening proof details, mobile navigation and console errors for both report languages. No external report-resource requests were observed.
- Dossier command arguments were parsed by the installed OpenLDAP client with a deliberately unreachable localhost endpoint. This checks accepted command syntax, not successful LDAPS PoC execution. The separate live read-only DACL/membership verification is recorded independently.
- Unit regressions cover partial failures, boundary inputs, offline publication and history. Live TLS failures remain failures. Container builds, Windows/macOS launchers, the complete supported-Python CI matrix, network interruption/large-forest load tests, external service integrations and every possible AD deployment were not exercised live.
- No full dependency-CVE audit, exhaustive property-specific AD access-check proof, cross-forest trust exploitation, active coercion, password spraying, credential dumping, certificate issuance or destructive PoC was performed. These must not be inferred from a passing read-only scan.
- The existing graph remains bounded; absence of a route is not evidence of absence. Legacy snapshots may lack group type, complete token membership, full descriptors or fresh transport evidence. Unknown visibility must remain explicit.
- Some older analyzers retain broad exception handling and local-date age calculations. Their exhaustive redesign was outside the validated changes; additional fixture-backed reviews should focus on access-control inheritance, service-specific runtime prerequisites and timezone-sensitive thresholds.
